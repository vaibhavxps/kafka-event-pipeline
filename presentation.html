Introduction & Problem Statement

The Challenge of Stream Ingestion at Scale

Traditional request-response architectures fail when confronted with unpredictable, bursty real-time workloads.

🔗

Monolithic Synchronous Coupling

Direct HTTP calls between microservices create fragile chains where one slow service causes cascading latency spikes and timeout drops.

⚠️

Flaw of CPU-Based Autoscaling

Standard Kubernetes HPA triggers on CPU/Memory thresholds. By the time consumer CPU spikes, thousands of messages are already backlogged.

💥

Data Loss on Transient Pod Failures

Without durable append-only distributed commit logs and explicit commit offset semantics, transient worker crashes lead to dropped or double-processed events.

📊

Observability Blindspots

Without native metric exposition, system operators cannot detect queue lag, consumer starvation, or throughput bottlenecks before end-users are impacted.

🔄 Ingestion & Buffering Subsystem

The Go producer publishes JSON payloads every 500ms using a LeastBytes partition balancer and BatchTimeout: 50ms. Kafka acts as a durable shock absorber, insulating down-stream workers from burst spikes.

📈 KEDA Reactive Scaling Loop

The KEDA controller polls Kafka every 15 seconds. If unconsumed queue depth exceeds 10 messages per pod, it dynamically scales the consumer deployment from 1 replica up to 10 replicas, shrinking back after cooldown.

Testing, Evaluation & Challenges

Validation Results & Engineering Challenges Solved

Key technical hurdles encountered during Kubernetes orchestration and how they were resolved.

⏳

Challenge 1: Pod Cold-Start Race Conditions

Problem: During cluster boot, producer and consumer pods started faster than the Kafka JVM broker, causing immediate crash-loops.
Solution: Embedded a lightweight BusyBox init-container with TCP probe script (until nc -z kafka 9092; do sleep 3; done) to enforce deterministic dependency sequencing.

🛡️

Challenge 2: Poison-Pill Deadlock Prevention

Problem: Malformed JSON messages previously caused unmarshal exceptions, causing consumer aborts and endless redelivery loops.
Solution: Implemented error isolation in consumeLoop: invalid payloads are logged with partition/offset and explicitly committed forward so the worker pipeline never freezes.

⚖️

Challenge 3: Scaling Oscillation (Flapping)

Problem: Rapid message bursts could trigger rapid scale-up followed immediately by premature pod termination.
Solution: Tuned KEDA configuration with a 15-second polling interval and a 60-second cooldown period (cooldownPeriod: 60) to stabilize pod lifecycles.

🔒

Challenge 4: Container Security & Image Bloat

Problem: Default Go build environments created 850MB+ images and executed as default root user.
Solution: Refactored into a 2-stage build: compiled static binary with -ldflags="-s -w", running inside Alpine 3.19 under non-root appuser (UID 1000), achieving a 16.8MB final image.
