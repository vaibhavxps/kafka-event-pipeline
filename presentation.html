Decoupled Services

Producers and consumers operate independently. Kafka acts as a durable, fault-tolerant buffer between them, enabling asynchronous communication.

📈

Elastic Scalability

KEDA monitors consumer lag and auto-scales consumer pods. The system adapts to traffic spikes without manual intervention or over-provisioning.

🔍

Built-in Observability

Every processed message increments a Prometheus counter. Operators get real-time visibility into throughput, lag, and system health.

🐳

Cloud-Native by Design

Multi-stage Docker images, Kubernetes Deployments, health probes, and init containers follow production-grade container orchestration patterns.

Problem Statement

The Challenge of Real-Time at Scale

  • 1 Monolithic Bottlenecks — Traditional request-response architectures create tight coupling between data producers and consumers, leading to cascading failures and inability to handle bursty workloads.
  • 2 Manual Scaling is Reactive — CPU/Memory-based HPA scaling responds to symptoms, not causes. By the time CPU spikes, thousands of events are already queued and SLAs are breached.
  • 3 Observability Gaps — Without embedded metrics, operators lack real-time visibility into processing throughput, making it impossible to diagnose lag or data loss before users are impacted.
  • 4 Data Loss Risk — Without durable message storage and proper offset management, transient consumer failures can result in dropped events — unacceptable for financial, IoT, or compliance workloads.
  • 5 Operational Complexity — Deploying, configuring, and maintaining distributed systems across containers and orchestrators demands a standardized, reproducible infrastructure-as-code approach.

Objectives

What We Set Out to Build

🚀

O1 — Event Producer

Build a Go service that generates structured JSON events at 2 events/sec and reliably publishes them to Kafka with graceful shutdown semantics.

⚙️

O2 — Event Consumer

Build a Go consumer group member that processes events with at-least-once delivery guarantees and exports Prometheus metrics.

📊

O3 — Observability

Expose kafka_messages_processed_total counter on a standard HTTP endpoint for Prometheus scraping.

🐳

O4 — Containerization

Create multi-stage Dockerfiles producing minimal, secure images under 20MB using Alpine base with non-root execution.

☸️

O5 — Orchestration

Provide Kubernetes Deployment manifests with health probes, resource limits, init containers, and Prometheus scrape annotations.

📈

O6 — Auto-Scaling

Configure KEDA ScaledObject to scale consumers based on Kafka consumer group lag with a threshold of 10 messages.
